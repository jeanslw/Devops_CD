## 性能优化 + 时间修正 + 同步时间显示
- **加载慢**：`RegistryService.__init__` 中每次都新建 `HarborClient`（会探测 API），改为延迟初始化 property `_harbor`，纯数据库查询不再触发 Harbor 探测
- **时间偏移**：`formatTime` 原来拼接 `Z` 后缀导致数据库本地时间（东八区）被解析为 UTC，造成 8 小时偏移。去掉 `Z`，加上 `isNaN` 安全校验
- **同步时间**：`get_repositories()` 返回格式从 `list` 改为 `{"repositories": [...], "last_sync": "..."}`，前端在"同步"按钮左边渲染 `<span id="registry-last-sync">` 显示上次同步时间
- **前端适配**：`loadRepositories()` 解析 `data.repositories` + `data.last_sync`；`triggerRegistrySync()` 同步完成后即时更新 last_sync 标签

## 时间显示修复（第三轮）
- **问题**：之前误判数据库存的是本地时间，去掉了 `formatTime` 的 `Z` 后缀。实际上 `_to_mysql_dt` 只是去掉了 Harbor 返回的 `Z`，数值仍是 UTC。去掉 Z 后浏览器当本地时间解析，diff 差 8 小时。
- **修复**：`formatTime` 恢复补 `Z` 后缀按 UTC 解析；`last_sync` 改为 `datetime.now(timezone.utc)` 统一 UTC
- **绝对时间**：去掉所有相对时间显示（"1小时前"等），统一显示 `YYYY-MM-DD HH:mm` 本地时间

## 扫描报告修复 + 优化
- **scan_overview key 硬编码**：改为动态探测第一个匹配 `vulnerability.report` 或 `scanner.adapter` 的 key
- **扫描报告优化**：`get_scan_report` 从实时请求 Harbor 改为从数据库缓存读取（秒开）；有漏洞数量时回退到实时请求 Harbor 获取详细列表，避免只显示汇总无详情
- **新增触发扫描**：`POST /api/registry/scan/trigger/` 调用 Harbor 重新扫描 + 前端 `[扫描]` 按钮
- **报告弹窗**：顶部统计"共有缺陷 X 个（危急/严重/中等/其他）"，表格：缺陷码/严重度/组件/版本/修复版本，底部 Harbor 链接
- **severity 中文映射**：Critical→危急, High→严重, Medium→中等, Low→其他
- **扫描报告漏洞数为 0 修复**：Harbor v2 返回的 `scan_overview.summary` 中 severity key 可能是大写（`Critical`/`High`）或嵌套在第二层 `summary` 中，原代码只取小写 `critical`/`high` 导致全为 0。`_list_artifacts_v2` 增加大小写+嵌套兼容提取；`RegistryService.get_scan_report` 改为**总是优先请求 Harbor API**（不再依赖数据库数量>0才回退），并新增 `_norm_summary()` 规范化 summary 格式
- **扫描报告第二波修复**：比对 PHP 实现发现 `_get_scan_v2` 两个问题：1) `additions/vulnerabilities` URL 用 `digest` 而非 `tag`；2) 返回值没解包 MIME key 内层 dict，导致 `live.get("vulnerabilities")` 取不到数据。改为用 `tag` URL + 遍历 key 解包内层 dict（参照 PHP）。`trigger_scan` v2 同样改用 `tag`
- **单仓库同步失败修复**：`syncCurrentRepo` 前端传 `_registryRepoName.split("/")[0]`（如 `mycode`），但 `sync_for_project` 在数据库按 `job_name` 匹配（如 `devops-glue`），导致不匹配。改为 `sync_for_project` 支持三种匹配：`job_name` 精确、`harbor_repository` 精确、`harbor_repository` 前缀匹配
- **Harbor UI 跳转链接错误修复**：`harbor_url` 的 `projects/` 段用了数据库 `project_name`（CI job_name 如 `php/devops-glue`），`repositories/` 段用了完整 `repo_name`（如 `mycode/devops-glue`）。Harbor UI 期望 `projects/{harbor_project}/repositories/{image_only}/artifacts/{digest}`。修复：`_get_scan_v2` 用已拆分的 `repo`（image 名）；`RegistryService.get_scan_report` 从 `repo_name` 拆出 harbor_project 和 harbor_repo
- **Harbor 不可达友好提示**：新增 `HarborUnavailableError` 异常类，`HarborClient._get/_post/_delete` 捕获 `ConnectionError`/`Timeout` 并转为该异常；`RegistryService._harbor` 初始化失败、`sync_all`/`sync_for_project`/`trigger_scan`/`get_scan_report`/`delete_artifact` 均捕获并返回友好错误；路由层统一 catch 返回 HTTP 503；后台定时同步区分 warn 不报 error
